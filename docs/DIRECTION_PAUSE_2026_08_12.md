## 2. 本次讨论确立的四个诊断

这四条都不在现有 75 篇文档里，是重启时最容易重新丢失的上下文。

### 2.1 仓库里有两个共用一个名字的项目

- **V1**：`cal/env/world.py` 的关节身体 + `SensorSuite`（视觉／触觉／本体感觉）
  + GRU 梯度学习。这是"模仿人的成长"的原始配置。
- **V2**：`point_world.py` / `randomized_occlusion_world.py` 的点世界（无关节
  身体）+ 二值占据观测 + 手写贝叶斯滤波，全栈无梯度学习。

V2 不是 V1 的下一版，是 V1 死后换了一个世界重来。具身度确实被逐步削掉了，
每次简化都是为了让某个门槛能过。这个换轨没有被作为"路线切换"记录在 README
里，因此很容易被误读为同一系统的连续演进。

V2 的 holdout 结论是在点世界拿到的，不会自动迁移到关节身体世界。

### 2.2 gate 链把依赖关系搞反了

[`M1_STAGE_REPORT.md`](experiments/M1_STAGE_REPORT.md) 的替代解释第 5 条自陈：

> 预测头要求"下一画面准确"，却没有要求模型把可控变化和不可控变化分解。因果
> 信息对降低平均 BCE 并非必要，所以模型丢弃它是合理的最优解。

而能让因果结构变得有收益的机制——[`RESEARCH_PLAN.md`](RESEARCH_PLAN.md) §11
M3 的「预测误差驱动探索」「学习进步驱动探索」「主动探索比随机探索使用更少
样本」——被锁在 M1 之后，全部是未勾选的空框，从未实现。

也就是说：M1 被要求在只有下一帧预测这个目标的情况下单独达标，而唯一可能让它
成功的目标函数在门槛链的下游。能力被要求逐个单独达标，而不是互相支撑地一起
生长。

### 2.3 三次失败都是捷径，代码一次都没错

| 阶段 | 诊断 |
| --- | --- |
| M1 | 环境不可辨识（三条二值臂共享基座与几何，稳定退化为同构臂混选）+ 目标函数不需要因果 |
| L0 V8 | environment problem rather than a model problem——隐藏位置是 `(k, seed 奇偶)` 的确定函数 |
| P1 | protocol-level——不做任何信念滤波的红队候选通过全部 18 个 gate；两轮 code review 报 P0/P1 = 0 |

结论：**冻结任何门槛前，必须先构造一个"用最笨的捷径达成该指标"的红队候选并
让它跑一遍。红队通过 = 门槛没测到想测的机制。** 这个习惯救了项目三次，是转向
任何新路线时最该保留的东西。

注意 `cal/model/motion_hypotheses.py` 的 `PauseLearner` 本身就是位置索引查表，
与击穿 P1 的那个「125 项误差表」候选同形。

### 2.4 缺的是发育理论，不是评测理论

仓库有 75 篇文档、14,863 行（对 44,695 行代码）。先想后写早已是主导活动。但
这些文档几乎全部在回答"怎么证明它做到了"。

四个问题接近空白：

1. **驱动力是什么**——什么让系统主动去学，而不是等着被训练。
2. **阶段是什么**——不是评测门槛，是能力的形态变化。
3. **上一阶段如何成为下一阶段的输入**——§11 的「技能复用」提了一句就没展开。
   这是"成长"与"分别学会几件事"的全部区别。
4. **怎么知道它在长而不是原地转**——这一项已经做到了极致。

[`MODALITY_SYSTEM.md`](MODALITY_SYSTEM.md) 是分类树，分类不是机制；它说了语言
长在具身概念之上，没有说什么力量把系统往上推。

## 3. 未决分叉（重启时先回答这个）

项目目标已明确为：**可自我成长、自我学习的具身系统（小孩成长为成人的过程），
不依赖大模型和大规模训练／推理，不要求每项能力满分。**

小算力这条约束**已经满足**，不需要专门工作：V1 GRU 仅 138,942 参数、
228,496 MAC/步、CPU 单步 0.118 ms；V2 手写贝叶斯更小。

未决的是"像人一样成长"的具体含义，两个选项做出来的系统完全不同：

- **（甲）发育阶段有固定顺序**——先自我、再物体、再因果、再语言。则需要写一份
  阶段规格 + 跃迁条件；V2 已有的实体结构可以作为先天先验保留。
- **（乙）顺序不重要，所有能力在同一个驱动力下一起生长**——则需要写一份驱动力
  规格，阶段是涌现的观察结果而非设计产物；V2 的实体结构原则上必须由系统自己
  长出来，不能直接给。

## 4. 重启时的第一步

共识是：**不从代码重启，也不从第 76 篇预注册重启。**

先补上第 2.4 节所说的那份文档——回答"它凭什么会做到"，而不是"怎么证明它做到
了"。硬要求是：每个概念必须能落到"系统里哪个变量在变"，否则又是一层分类树。
"好奇心"不算，"预测误差的时间导数作为动作选择的效用"才算。

曾经提议过一个最小起步实验：**主动探索是否比随机探索用更少样本发现环境
规律**（来自 §11 自己的验收标准）。它的优点是不受同构臂不可辨识问题污染，
现有世界和 trainer 就能跑。但该提议在暂停前未被采纳，重启时应重新评估，不要
默认执行。

## 5. 重启时不要做的事

- **不要直接跑 `cal-train` 重做 V1。**
  [`M1_EXTENDED_STAGE_REPORT.md`](experiments/M1_EXTENDED_STAGE_REPORT.md) 的
  门控决定第 4 条要求重启必须先提出**改变可观测性或生成模型假设**的新预注册，
  而不是再微调当前包络分类家族。直接重跑违反项目自己的停止条件，产出没有证据
  效力。
- **不要靠改外观来打破臂的同构性。** 身体与物体外观强度不同时，纯视觉阈值
  直接得到 IoU 1.0。要打破同构性只能靠因果（例如每条臂只响应动作子集）。
- **不要重用已消费的留出集。** L0 V8 留出集已于 2026-07-28 消费。新主张需要新
  预注册的划分，其内容必须保持在开发过程之外。
- **不要在未回答第 3 节的分叉前推进具体实现方案。**
